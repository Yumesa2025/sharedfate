# SharedFate 서버 설치

SharedFate 서버를 **처음 여는 사람**을 위한 문서입니다. 바닐라 서버를 운영해 본 적이 없어도
그대로 따라 하면 됩니다.

> ⚠ **0.27.0-dev 부터는 마인크래프트 26.3 전용입니다. 26.2 에서는 아예 켜지지 않습니다.**
> 서버와 모든 클라이언트가 **마인크래프트 자체를 26.3 으로** 올려야 합니다. SharedFate 판을
> 서로 맞추더라도 **마인크래프트 판이 다르면** 함께 쓸 수 없습니다.
> 26.2 에 머무를 분은 0.26.7-dev 를 그대로 쓰십시오.

| | |
|---|---|
| Minecraft | Java Edition **26.3** |
| Fabric Loader | **0.19.5** 이상 |
| Fabric API | **0.161.0+26.3** 이상 |
| Java | **25** 이상 |
| 권장 메모리 | 4인 기준 **4GB** (`-Xmx4G`) |

> **서버와 모든 클라이언트는 SharedFate 판이 같아야 합니다.** 통신 규약이 다르면 접속하는
> 순간 거부됩니다. 이상하게 동작하는 대신 바로 알 수 있게 한 것입니다.

---

## 1. 서버 폴더 만들기

빈 폴더를 하나 만들고 Fabric 서버를 설치합니다.

1. [Fabric Installer](https://fabricmc.net/use/server/) 로 **Minecraft 26.3 / Loader 0.19.5
   이상** 서버를 만듭니다. 창으로 만드실 때 **서버 JAR 를 받는 항목을 켜십시오.** 명령줄이
   편하면 이렇게 합니다.

   ```
   java -jar fabric-installer.jar server -mcversion 26.3 -loader 0.19.5 -downloadMinecraft
   ```

   > ⚠ **`-downloadMinecraft` 를 빼면 안 됩니다.** 빼면 `fabric-server-launch.jar` 만 생기는데
   > 그것은 600바이트짜리 껍데기라 그것만으로는 서버가 켜지지 않습니다. 마인크래프트 본체
   > (`server.jar`, 60MB 쯤)가 같은 폴더에 있어야 합니다. 설치가 끝나면 `server.jar` 이 있는지
   > 눈으로 확인하십시오.

`eula.txt` 는 만들지 않아도 됩니다. 재시작 스크립트가 **처음 켤 때 한 번 물어보고** 만듭니다
(아래 3번).

## 2. 모드 넣기

서버 폴더에 `mods` 폴더를 만들고 **JAR 두 개**를 넣습니다.

```
서버폴더/
  fabric-server-launch.jar
  server.jar                    <- 마인크래프트 본체. 없으면 1번을 다시
  server.properties             <- hardcore=true · white-list=false
  mods/
    sharedfate-<판>.jar
    fabric-api-0.161.0+26.3.jar
```

Fabric API 는 [모드 배포처](https://modrinth.com/mod/fabric-api)에서 **26.3 용**을 받습니다.
릴리스의 서버 ZIP 을 받았다면 이 구조가 이미 들어 있습니다.

> ⚠ **26.2 에서 올라오는 서버라면 `mods` 의 옛 JAR 두 개를 먼저 빼십시오.** 옛 SharedFate JAR
> 이 함께 있으면 중복 로드로 서버가 뜨지 않고, 26.2 용 Fabric API(`fabric-api-*+26.2.jar`)는
> 이름이 달라 덮어써지지 않은 채 남아 같은 일이 일어납니다.

## 3. 재시작 루프로 켜기 — **이 단계를 건너뛰면 안 됩니다**

팀이 전멸하면 **다음 회차의 새 월드가 시작됩니다.** 그런데 모드는 월드를 직접 지우지
않습니다. 서버 루트에 표식 파일(`.sharedfate-world-reset.pending`)을 하나 남기고 **정상
종료할 뿐**이고, 표식에 적힌 월드 폴더를 지우고 서버를 다시 켜는 일은 **재시작 루프
스크립트**가 합니다.

**그래서 `java -jar` 로 직접 띄우면 전멸한 순간 서버가 꺼진 채로 남습니다.**

릴리스의 서버 ZIP 이나 저장소 `scripts/` 에 네 파일이 있습니다. 서버 폴더에 복사하십시오.

| 운영체제 | 켜는 파일 | 실제 일을 하는 파일 |
|---|---|---|
| Windows | `start-sharedfate-server.bat` | `sharedfate-server-loop.ps1` |
| Linux · macOS | `start-sharedfate-server.sh` | `sharedfate-server-loop.sh` |

**Windows**

```bat
start-sharedfate-server.bat
```

**Linux · macOS**

```bash
chmod +x start-sharedfate-server.sh sharedfate-server-loop.sh
./start-sharedfate-server.sh
```

처음 켜면 **Minecraft EULA 동의를 한 번 묻습니다.** 링크를 읽고 `y` 를 입력하면 `eula.txt` 가
만들어지고 서버가 이어서 켜집니다. 손으로 파일을 만들 필요가 없고, 다음부터는 묻지 않습니다.

`eula=true` 는 설정값이 아니라 **동의 서명**이라 배포 ZIP 에 미리 넣어 둘 수 없습니다. 그래서
배포본에는 `eula.txt` 가 없고, 서버를 여는 사람이 직접 한 번 누르게 되어 있습니다.

창 없이 돌리는 곳(작업 스케줄러 · systemd · 호스팅 패널)에서는 물어볼 수 없으므로 미리
동의를 넘기십시오. 넘기지 않으면 무엇을 해야 하는지 적고 멈춥니다.

| 운영체제 | 미리 동의 |
|---|---|
| Windows | `-AcceptEula` |
| Linux · macOS | `--accept-eula` |

메모리는 두 켜는 파일 안의 `-MinMemory`·`-MaxMemory`(Windows) 또는 `--min`·`--max`(Linux)
값을 고쳐서 정합니다.

> **서버 창을 닫거나 부모 프로세스를 끊으면 서버도 함께 죽습니다.** 종료 기록이 남지 않아
> 나중에 원인을 찾기 어렵습니다. 내릴 때는 **콘솔에 `stop`** 을 치십시오.
>
> **서버가 켜져 있는 동안 `mods` 의 JAR 를 바꾸지 마십시오.** Fabric 은 클래스를 필요할 때마다
> JAR 에서 읽으므로, 실행 중에 파일이 바뀌면 아직 읽지 않은 클래스를 찾는 순간 죽습니다.

### 월드는 정확히 하나만, 검증한 뒤에 지웁니다

루프 스크립트는 표식에 적힌 경로가 아래를 **모두** 만족할 때만 지웁니다. 하나라도 어긋나면
아무것도 지우지 않고 멈춥니다.

- 표식 파일이 **서버 루트**에 있고, 정해진 머리글로 시작하는 **두 줄**일 것
- 월드 경로가 **절대 경로**일 것
- 그 폴더의 **부모가 정확히 서버 루트**일 것 (두 단계 아래도 안 됩니다)
- 서버 루트 자체가 아닐 것
- **심볼릭 링크·정션이 아닐** 것

**운영 중인 월드는 먼저 백업하십시오.** 전체 서버 폴더, 링크, 표식과 일치하지 않는 경로를
초기화 대상으로 쓰면 안 됩니다.

## 4. 설정 파일

서버 ZIP 과 저장소 `scripts/` 에 `server.properties` 기본값이 들어 있습니다. 바닐라 기본값에서
셋만 손본 것입니다.

| 값 | 왜 |
|---|---|
| `hardcore=true` | 전멸 시 사망 화면이 「게임 오버」로 뜹니다 |
| `white-list=false` | 26.3 기본값은 `true` 입니다. 그대로면 **아무도 못 들어옵니다** |
| `motd=` (빈 값) | 모드가 증강 개수까지 맞춘 문구로 채웁니다 |

> ⚠ **`hardcore` 는 월드가 만들어질 때 `level.dat` 에 한 번 박히고, 그 뒤로는 이 파일을 보지
> 않습니다.** 이미 만든 월드를 하드코어로 바꾸려면 파일만 고쳐서는 안 됩니다 — 서버를 내리고
> `hardcore=true` 로 둔 다음 `world` 를 지우고 다시 켜십시오. 아니면 **다음 회차부터 저절로
> 맞습니다** (회차가 바뀔 때 월드가 새로 만들어집니다). `white-list` 는 매번 읽으므로 재시작만
> 하면 됩니다.

> ⚠ **이미 돌고 있는 서버에는 이 파일을 풀지 마십시오.** 포트·시드·화이트리스트처럼 그 서버에만
> 맞춰 둔 값이 날아갑니다. 그 파일만 빼고 풀고, 원래 쓰던 파일에서 `hardcore` 만 보십시오.

모드 설정은 따로입니다. 서버를 한 번 켜면 `config/sharedfate.json` 하나가 생깁니다. **증강과
세트 정의는 모드 안에 들어 있어 설정 파일로 나오지 않습니다** — 판을 올릴 때 지울 것이 없습니다.

`config/sharedfate.json` 의 기본값입니다.

```json
{
  "maxTeamSize": 4,
  "sharedMaxHealth": 20.0,
  "shareEnderChest": true,
  "shareExperience": true,
  "shareStatusEffects": true,
  "damageAlertDurationTicks": 30,
  "requireClientMod": true,
  "perkTestCommands": false,
  "overrideServerMotd": true,
  "dragonHealthPerMember": 600
}
```

- **`requireClientMod`** — 모드가 없는 클라이언트의 접속을 막습니다. 끄면 공유는 되지만
  화면 표시가 전혀 없어 무엇이 일어나는지 알 수 없습니다.
- **`perkTestCommands`** — 증강을 직접 넣고 빼는 운영자 전용 시험 명령입니다.
  **실제로 노는 서버에서는 켜지 마십시오.** 켜면 접속자마다 경고를 받고, 한 번이라도 쓴 팀은
  회차에 「정상 회차가 아닙니다」 표식이 붙습니다.
- **`overrideServerMotd`** — 서버 목록에 뜨는 설명(MOTD)을 모드가 손봅니다.
  **0.29.1-dev 부터 기본값이 켜짐입니다.**
  - **아무도 안 썼으면 채웁니다** — `motd` 가 바닐라 기본값(`A Minecraft Server`)이거나 비어
    있으면 「SharedFate · 체력·허기·인벤 공유 · 증강 N개」를 넣습니다. 받아서 서버를 연
    사람이 **아무것도 안 해도** 무슨 서버인지 목록에 뜹니다
  - **직접 썼으면 숫자만 맞춥니다** — 그 글 안에 「증강 N개」가 있으면 그 자리만 실제 값으로
    갈아 끼웁니다. 그 모양이 없으면 **아무것도 하지 않습니다.** 남이 쓴 글은 덮어쓰지
    않습니다
  - ⚠ 손보는 순간 `server.properties` 가 저장됩니다. 나중에 꺼도 **마지막에 써진 MOTD 는
    파일에 남습니다** — 되돌리려면 손으로 고쳐야 합니다
- **`dragonHealthPerMember`**(기본값 600) — 팀 인원 한 명당 엔더 드래곤 최대 체력입니다. 바닐라는 200 이고,
  인원은 접속자가 아니라 팀 명단으로 셉니다. 이 값은 난이도가 아니라 전투 길이를 정합니다.
  설정 파일에 이 줄이 없으면 600 으로 읽힙니다.
  ⚠ **팀 설정에서 「드래곤 시련」을 끈 팀에게는 이 값이 읽히지 않습니다**(시련은 기본값이 꺼짐입니다).
  ⚠ **0 으로 두면 서버 전체에서 드래곤 강화·시련·엔드 전원 소환이 함께 꺼집니다.**
- **`singleTeamOnly`**(기본값 켜짐) — 켜져 있으면 팀이 이미 있을 때 `/shareteam create` 를 거부합니다.
  ⚠ **끈 서버에서도 드래곤 시련은 한 번에 한 팀입니다.** 시련을 켠 팀이 엔드에서 싸우는 동안 다른 팀이
  들어오면 그 팀의 전투는 **시련 없이(바닐라 드래곤전)** 열리고 채팅으로 까닭을 알립니다. 시련의 상태가
  팀마다 따로 있지 않아서입니다.

### 판을 올릴 때 지울 것은 없습니다 (0.26.7-dev 부터)

예전에는 `config/sharedfate-perks.json` 과 `config/sharedfate-sets.json` 을 **판마다 둘 다
손으로 지워야** 했습니다. 두 파일이 JAR 안의 정의보다 우선하는데 판을 올려도 덮어써지지
않았기 때문입니다. 하나만 지우면 반쪽이 옛 정의로 읽히는데 오류도 나지 않아 더 나빴습니다.

**이제 증강·세트 정의는 모드 안에만 있습니다.** JAR 만 바꾸면 끝입니다.

예전 판에서 올라오는 서버에는 그 두 파일이 남아 있을 수 있습니다. **읽지 않으므로 그대로
두어도 해가 없고**, 지우셔도 됩니다. 서버가 뜰 때 한 번 알려 줍니다. 다만 그 파일의 값을 직접
고쳐 쓰고 계셨다면 **그 내용은 이제 반영되지 않습니다.**

## 5. 접속

같은 SharedFate 판을 넣은 클라이언트로 서버 주소에 접속합니다. 클라이언트 설치는 저장소
README 의 「클라이언트 설치」에 있습니다.

접속하면 서버 로그에 그 사람의 클라이언트 판이 한 줄 남습니다.

```
[CLIENT] 플레이어1 — sharedfate 0.28.0-dev
```

## 6. 게임 시작

1. 아무나 팀을 만듭니다 — `/shareteam create <팀 이름>`
2. 리더가 팀원을 넣습니다 — `/shareteam invite <플레이어>`
3. 리더가 시작합니다 — `/shareteam start` 로 무엇이 사라지는지 본 뒤
   `/shareteam start confirm`

**시작하는 순간 모든 아이템이 삭제되고**(드랍이 아닙니다) 공유 경험치가 0이 되며, 월드 시각이
1일차 아침으로 돌아가고 접속 중인 팀원이 스폰으로 모입니다. 되돌릴 수 없습니다.

**팀 설정 여덟 가지는 만들 때만 정하고 그 뒤로는 바꿀 수 없습니다.**

```text
/shareteam create [perks on|off] [damagealert on|off] [deathalert on|off]
                  [difficulty on|off] [dragontrials on|off]
                  [health <20~40>] [swap off|<1~120>] [reroll <0~15>] <팀 이름>
```

> **사망 알림을 끄면(`deathalert off`) 죽은 기록이 채팅에도 서버 로그에도 남지 않습니다.**
> 모드가 사망 메시지를 지우는데 서버 로그도 채팅을 받아 적는 자리이기 때문입니다. 나중에
> 전멸 원인을 쫓을 생각이라면 켜 두는 편이 낫습니다.

## 백업과 초기화

서버를 내린 뒤에 하십시오.

| 무엇 | 파일 |
|---|---|
| 월드 | `world/` |
| 회차 번호 | `sharedfate-run-state.json` |
| 피해 기록 | `sharedfate-damage-history.json` |
| 팀 명단 | `sharedfate-team-roster.json` |

**팀 명단은 월드와 별개입니다.** `world/` 만 지우면 팀이 그대로 살아남습니다. 전부
초기화하려면 위 네 가지를 함께 지우십시오.
