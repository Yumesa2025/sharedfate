# SharedFate

체력 하나, 인벤토리 하나로 최대 네 명이 엔더 드래곤을 잡는 협동 로그라이크입니다.
Minecraft Java Edition 26.3 / Fabric 용입니다.

전멸하면 월드가 통째로 사라지고 새 월드에서 다음 회차가 시작됩니다. 엔더 드래곤을 잡으면
그 회차가 승리로 끝납니다. 그사이 팀은 공유 레벨이 오를 때마다 **증강**을 하나씩 골라,
회차마다 다른 몸이 되어 다시 출발합니다.

> **[공식 사이트](https://yumesa2025.github.io/sharedfate/)** — 설치부터 증강 96개 전체
> 목록까지. 증강을 등급·유형으로 걸러 볼 수 있습니다.

### 한 몸입니다

체력과 배고픔, 경험치, 포션 효과가 팀에 하나씩만 있습니다. 인벤토리도 54칸(9×6) 하나를
넷이 함께 쓰고 방어구 네 칸과 오프핸드, 엔더상자까지 공유합니다.

그래서 한 명이 용암에 빠지면 네 명이 같이 탑니다. 한 명이 먹으면 네 명이 배부르고, 한 명이
캔 다이아몬드는 캐는 순간 모두의 것입니다. 팀의 최대 체력은 만들 때 20에서 40 사이로
정합니다.

개인으로 남는 것은 지금 들고 있는 칸과 서 있는 자리뿐입니다. 아군이 어느 칸을 들고 있는지는
핫바에 빨간 테두리로 보입니다.

### 레벨이 오르면 증강을 고릅니다

공유 레벨 5·10·15·20·25·30·35·40 — 한 회차에 여덟 번, 팀원 한 명에게 카드 세 장이
펼쳐집니다. 고른 사람이 누구든 **효과는 팀 전체에 걸립니다.**

등급은 실버·골드·프리즘 셋이고 15레벨 구간만 프리즘으로 고정입니다. 세 장이 다 마음에 들지
않으면 회차당 세 번까지 다시 뽑을 수 있습니다.

**대부분의 증강에는 대가가 붙어 있습니다.** 최대 체력이 6 늘어나는 대신 머리 방어구를 쓸 수
없고, 채굴 속도가 두 배가 되는 대신 공격력이 깎이는 식입니다. 무엇을 내줄지가 곧 이번 회차의
성격이 됩니다.

기본 풀은 96개입니다 — 실버 35 · 골드 36 · 프리즘 25. 전체 목록은
**[docs/증강-목록.md](docs/증강-목록.md)** 에 있습니다.

### 같은 결을 모으면 세트가 열립니다

증강마다 유형이 붙어 있습니다 — 채굴 · 화력 · 기동 · 방어 · 보급 · 무기 · 도박 · 사냥 ·
생존 · 교환 · 회복 · 가호 · 개척 · 결속, 열넷입니다. 같은 유형을 둘·셋·넷 모을 때마다 추가 보상이
켜지고 **단계는 누적됩니다.**

화력을 넷 모은 팀은 공격력 +2 와 흡혈 15% 와 근접 사거리 +50% 를 한꺼번에 답니다. 14유형
28단계가 있고, 지금 무엇을 몇 개 모았는지는 화면 왼쪽 위에 늘 보입니다.

그래서 증강 선택이 한 장짜리 결정으로 끝나지 않습니다. 당장 센 카드와, 이미 둘을 모아 둔
유형의 세 번째 카드 사이에서 고르게 됩니다.

### 경험치는 이제 증강의 화폐입니다

경험치가 증강을 여는 자원이 된 이상, 인챈트에 레벨을 쓰면 두 체계가 서로를 갉아먹습니다.
인챈트를 할 때마다 다음 증강이 멀어지기 때문입니다. 그래서 **레벨을 내던 자리를 전부
다이아몬드로 옮겼습니다.**

- **인챈트 탁자** — 경험치 레벨을 아예 보지 않습니다. 요구 레벨도 소모도 없어 **레벨 0으로도
  세 칸을 전부** 인챈트할 수 있고, 대신 다이아몬드 10개를 냅니다. 청금석 칸 아래에 다이아몬드
  전용 칸이 있습니다
- **모루** — 작업 내용과 상관없이 **언제나 다이아몬드 10개**입니다. 경험치를 쓰지 않으므로
  「비용이 너무 비쌉니다」도 뜨지 않습니다. 여러 번 고친 장비를 끝까지 씁니다
- **대장장이 작업대** — 네더라이트 업그레이드에 **형판이 필요 없습니다.** 다이아몬드 장비와
  네더라이트 주괴만 있으면 됩니다. 형판을 끼운 옛 방식도 그대로 됩니다

### 클라이언트 설치

1. Minecraft 26.3과 Fabric Loader 0.19.5 이상을 설치합니다.
2. 게임과 런처를 완전히 종료합니다.
3. 클라이언트 ZIP을 풀어 안내 파일을 읽습니다.
4. `%appdata%\.minecraft\mods`에서 이전 `sharedfate-*.jar`를 제거합니다.
   **26.2 에서 올라오는 경우 26.2 용 Fabric API(`fabric-api-*+26.2.jar`)도 함께 빼십시오.**
   새로 넣는 `fabric-api-0.161.0+26.3.jar` 는 이름이 달라 덮어써지지 않고, 둘이 함께 남으면
   Fabric API 중복 로드로 게임이 아예 켜지지 않습니다.
5. ZIP의 `mods` 폴더 안 JAR 두 개를 게임의 `mods` 폴더에 복사합니다.
6. Fabric 프로필로 게임을 실행해 같은 버전의 서버에 접속합니다.

Java 25가 필요합니다. SharedFate JAR만 받았다면 Fabric API
`0.161.0+26.3` 이상도 직접 설치해야 합니다.

### 업데이트와 제거

- 업데이트: 게임을 종료한 뒤 이전 SharedFate JAR를 새 JAR로 교체합니다. 여러 버전을 동시에
  두지 마세요.
- 제거: 서버를 정상 종료하고 월드를 백업한 뒤 서버와 모든 클라이언트에서 SharedFate JAR를
  제거합니다. 공유 상태가 들어 있는 운영 월드를 바닐라로 바로 열지 않는 것을 권장합니다.

## 서버 운영

설치부터 첫 회차 시작까지는 **[docs/서버-설치.md](docs/서버-설치.md)** 에 따로 적었습니다.
바닐라 서버를 운영해 본 적이 없어도 그대로 따라 하면 됩니다.

요약하면 이렇습니다.

1. Fabric 서버(**Minecraft 26.3 / Loader 0.19.5 이상**)를 준비합니다.
2. `mods` 에 SharedFate JAR 와 Fabric API 를 넣습니다.
3. **재시작 루프 스크립트로 켭니다.** 서버 ZIP 이나 저장소 `scripts/` 에 있습니다.
   - Windows — `start-sharedfate-server.bat`
   - Linux · macOS — `start-sharedfate-server.sh`

**`java -jar` 로 직접 띄우면 안 됩니다.** 팀 전멸 시 모드는 월드를 직접 지우지 않고 서버
루트에 표식 파일을 남기고 정상 종료할 뿐입니다. 표식에 적힌 월드 폴더를 지우고 서버를 다시
켜는 일은 루프 스크립트가 하므로, 루프 없이 띄우면 전멸한 순간 서버가 꺼진 채로 남습니다.

루프 스크립트는 표식에 적힌 경로가 **절대 경로이고, 부모가 정확히 서버 루트이고, 서버 루트
자체가 아니고, 심볼릭 링크·정션이 아닌 실제 폴더**일 때만 지웁니다. 하나라도 어긋나면
아무것도 지우지 않고 멈춥니다. 그래도 **운영 월드는 먼저 백업하세요.**

**서버가 켜져 있는 동안 `mods` 의 JAR 를 바꾸지 마십시오.** Fabric 은 클래스를 필요할 때마다
JAR 에서 읽으므로, 실행 중에 파일이 바뀌면 아직 읽지 않은 클래스를 찾는 순간 죽습니다.

**판을 올릴 때 지울 설정 파일은 없습니다.** 증강과 세트 정의는 모드 안에 들어 있어
`config/` 로 나오지 않습니다. 예전 판에서 올라와 `config/sharedfate-perks.json` 이나
`config/sharedfate-sets.json` 이 남아 있어도 읽지 않으므로 그대로 두어도 됩니다.

## 주요 기능

맨 위 소개에서 다루지 않은 세부입니다.

- 공유 저장공간 기본 54칸(9×6): 핫바 9 + 메인 27 + 추가 18. 증강 「짐꾼」이 한 줄을 더 열어
  63칸(9×7)이 됩니다
- 흡수 체력과 포화도까지 공유합니다
- 피격 알림·피격 연출과 사망 알림 — 팀을 만들 때 켜고 끕니다
- 음식 초과 영양 버퍼 — 허기가 가득 찬 뒤에 먹은 것이 버려지지 않고 쌓입니다
- 팀 전멸 시 안전한 다음 회차 시작, 드래곤 승리와 피해 통계 책

주손 선택 슬롯과 위치는 기본적으로 개인별입니다. 팀 가입 시 개인 아이템은 현재 위치에
드랍되고 개인 경험치는 팀 공유 풀에 합쳐집니다. 일반 탈퇴자는 빈 인벤토리와 경험치 0으로
분리됩니다.

## 명령어

대부분은 `/shareteam` 창에서 할 수 있습니다. 명령으로도 그대로 됩니다.

**`/shareteam` 은 `/st` 로 줄여 쓸 수 있습니다.** 하위 명령은 모두 같고, 인자 없는 `/st` 도
팀 화면을 엽니다.

```text
/shareteam                      팀 화면 열기 (모드가 있는 클라이언트)
/shareteam help
/shareteam create <팀 이름>
/shareteam create [perks on|off] [damagealert on|off] [deathalert on|off]
                  [difficulty on|off] [dragontrials on|off]
                  [health <20~40>] [swap off|<1~120>] [reroll <0~15>] <팀 이름>
/shareteam start                무엇이 사라지는지 먼저 보여 줍니다 (리더)
/shareteam start confirm        회차를 실제로 시작합니다. 되돌릴 수 없습니다
/shareteam invite <플레이어>     상대를 곧바로 팀에 넣습니다 (리더, 시작 전에만)
/shareteam status               지금 정해져 있는 설정 전부
/shareteam swap status          다음 위치 교환까지 남은 시간
/shareteam difficulty status    난이도가 지금 몇 %까지 올랐는지
/shareteam perk
/shareteam perk list
/shareteam storage            팀 창고를 엽니다 (`/창고` 로도 됩니다)
/shareteam list
/shareteam version              내 클라이언트와 서버가 같은 판인지
/shareteam version all          접속 중인 전원의 판 (운영자 전용)
/shareteam leave
/shareteam disband confirm
/shareteam reset                서버를 처음 상태로 되돌립니다 (운영자 전용)
/yes  ·  /수락                   위 초기화를 확정합니다 (30초 안에, 친 사람만)
```

**`/shareteam reset` 은 서버를 통째로 되돌립니다.** 회차·팀·보유 증강·피해 기록·월드가 전부
사라지고 1회차로 돌아갑니다. 무엇이 지워지는지 먼저 보여 주고 기다리며, 확정하면 5초 뒤
서버가 종료되고 재시작 루프 스크립트가 새 월드로 다시 엽니다. `/shareteam yes` ·
`/st 수락` 으로도 확정할 수 있습니다.

> ⚠ **재시작 루프 스크립트로 켠 서버에서만 쓰십시오.** `java -jar` 로 직접 띄운 서버는
> 꺼진 채로 돌아오지 않습니다.

**초대에 수락 절차가 없습니다.** 리더가 `invite` 를 치면 상대가 곧바로 들어옵니다.
그때 상대의 개인 아이템은 있던 자리에 드랍되고 개인 경험치는 공유 풀에 합쳐지므로,
부르기 전에 미리 알려 주는 편이 좋습니다.

**사람은 회차를 시작하기 전에 모읍니다.** 시작한 뒤에는 초대가 막힙니다 — 도중에 들어오면
증강을 고르는 구간을 건너뛴 채로 남이 모은 인벤토리를 쓰게 되어 같은 회차를 서로 다른
조건으로 겪습니다. 사람을 바꾸려면 팀을 해체하고 다시 만듭니다.

### 회차는 「게임 시작」으로 시작합니다

팀을 만들면 「시작 대기」이고, 리더가 `/shareteam start confirm` 이나 팀 화면의 단추를
눌러야 1회차가 시작됩니다. **첫 회차 전에 한 번만 누릅니다** — 전멸해서 새 월드로 넘어간
뒤에는 저절로 「진행 중」입니다.

시작하는 순간 **모든 아이템이 삭제되고**(드랍이 아닙니다) 공유 경험치가 0이 되며, 월드
시각이 1일차 아침으로 돌아가고 접속 중인 팀원이 스폰으로 모입니다. 되돌릴 수 없으므로
`/shareteam start` 는 무엇이 사라지는지 보여 주기만 하고, `confirm` 을 붙여야 실제로
시작합니다.

시작 전에는 증강 구간·위치 교환·난이도 상승이 돌지 않고 팀원이 죽지도 않습니다.

### 팀 설정은 만들 때 한 번만 정합니다

**증강 사용 여부 · 공유 최대 체력 · 위치 교환 · 난이도 상승 · 피격 알림 · 사망 알림 ·
드래곤 시련 · 증강 다시 뽑기 횟수** 여덟 가지는 `/shareteam create` 에서만 정하고 **그 뒤로는 바꿀 수
없습니다.** 회차가 굴러가는 중에 규칙이 바뀌면 같은 회차의 앞뒤가 달라지기 때문입니다.
바꾸려면 팀을 해체하고 다시 만들어야 합니다.

적지 않은 것은 기본값입니다 — **증강은 켬**, **위치 교환은 5분 주기로 켬**, 두 알림과
난이도 상승과 드래곤 시련은 끔, 최대 체력은 서버 설정값, 증강 다시 뽑기는 회차당 3회. 지금 값이 얼마인지는
`/shareteam status` 로 봅니다.

`difficulty on` 으로 만든 팀은 **30분마다 적대적 몹의 최대 체력과 공격력이 4%p 씩**
오릅니다(최대 +100%). 엔더 드래곤은 제외입니다. 시간은 팀원이 접속해 있는 동안만 흐릅니다.

`dragontrials on` 으로 만든 팀은 엔더 드래곤이 인원에 비례해 세지고 시련 카드가 뜹니다.
끄면(기본값) 바닐라 엔더 드래곤전입니다.

## 팀 화면

`/shareteam`(`/st`) 을 인자 없이 치거나, **인벤토리(E) 왼쪽 위의 단추**를 누르면 창이
열립니다. 단추는 팀이 있느냐에 따라 달라집니다.

- **팀이 없을 때** — 「팀 생성」 하나뿐이고, 누르면 **「팀」 탭이 펴진 채로** 열립니다
- **팀이 있을 때** — 「SharedFate」 와 「현재 증강」 둘

탭은 다섯입니다.

| 탭 | 하는 일 |
|---|---|
| 현황 | 회차 상태, 팀 이름, 접속 인원, 팀 레벨, 다음 증강까지 남은 레벨, 공유 체력, 교환 주기, 증강 사용 여부 |
| 팀 | 팀 만들기(여덟 가지 설정), 접속자별 초대(**시작 전에만**), 게임 시작, 나가기·해체 |
| 설정 | 팀을 만들 때 정한 값을 보여 주기만 합니다 — **리더만** |
| 증강 | 보유 증강 목록, 증강 선택창 열기 |
| 능력치 | 증강이 능력치를 얼마나 바꿨는지 |

팀 이름을 적기 전에는 「팀 만들기」 단추가 회색으로 눌리지 않습니다.

## 인벤토리 화면의 능력치

인벤토리(E)를 열면 왼쪽에 여덟 줄이 세로로 보입니다. 창을 닫지 않아도 무기를 바꾸면
숫자가 따라옵니다.

| 줄 | 뜻 |
|---|---|
| 최대 체력 · 공격력 · 공격 속도 · 방어력 · 이동 속도 | 지금 내 몸에 걸려 있는 값 |
| 받는 피해 | 증강이 바꾼 「맞으면 얼마나 아픈가」 |
| 몹 체력 · 몹 공격력 | 증강과 난이도 상승이 함께 만든 「이 판이 얼마나 험한가」 |

**바닐라 기본값 → 지금 값** 순으로 적고, 좋아졌으면 초록 나빠졌으면 빨강입니다.
받는 피해와 몹 두 줄은 **오르는 것이 나쁜 값**이라 색이 반대입니다.

창 왼쪽에 남는 자리는 GUI 배율과 화면 크기에 따라 달라지므로, 좁으면 이름을 줄이고
더 좁으면 두 줄로 접습니다. 그래도 모자라면 단추만 남기고 감춥니다 — 그때는 팀 화면의
「능력치」 탭에서 온전한 모습으로 볼 수 있습니다.

## 증강 설정

증강 목록(실버 34 · 골드 35 · 프리즘 25)과 세트 정의는 **모드 안에 들어 있습니다.**
`config/` 로 나오지 않으므로 **판을 올릴 때 지울 것이 없습니다.** 값을 바꾸려면 저장소의
`sharedfate-perks-default.json`·`sharedfate-sets-default.json` 을 고쳐 다시 빌드하십시오.

> 0.26.5-dev 까지는 두 정의를 `config/` 로 꺼내 놓고 그 파일만 읽었습니다. 판을 올려도
> 덮어쓰지 않아 **판마다 두 파일을 손으로 지워야** 했고, 하나만 지우면 반쪽이 옛 정의로
> 읽히는데 오류도 나지 않았습니다. 남아 있는 옛 파일은 이제 읽지 않습니다.

한 구간에는 같은 등급 후보 3개만 나오고, **한 번 고른 증강은 그 회차 동안 다시 나오지
않습니다.** 한 회차의 여덟 구간 가운데 **15렙만 프리즘 고정**이고, 나머지 일곱 구간은
확률로 정해집니다.

**확률표는 고정이 아니라 프리즘이 나올 때마다 바뀝니다.**

| 확률로 나온 프리즘 | 실버 | 골드 | 프리즘 |
|---|--:|--:|--:|
| 0번 | 45 | 45 | 10 |
| 1번 | 46 | 51 | 3 |
| 2번 | 50 | 50 | **0** |

그래서 확률로 나오는 프리즘은 회차당 2번까지이고, **15렙 고정을 더해 최대 3번**입니다
(15렙 고정은 이 수에 넣지 않습니다). 해당 등급의 후보가 3개에 모자라면 다른 등급이 채웁니다.

증강이 이 표를 흔들기도 합니다 — 「원정 준비물」을 가진 팀은 프리즘 확률이 3%p 오르고
(골드에서 뺍니다) 실버가 후보에서 통째로 빠지며, 그 몫은 전부 골드로 넘어갑니다.

### 증강 시험 명령 — 실제로 노는 서버에서는 켜지 마십시오

증강을 하나하나 확인하려고 만든 **운영자 전용** 명령이 있습니다. 구간과 레벨을 건너뛰고
증강을 직접 넣고 뺍니다.

```text
/shareteam perktest status
/shareteam perktest owner              「고른 사람만」 걸리는 증강의 지금 주인
/shareteam perktest give <증강id>      (증강 id 는 자동 완성됩니다)
/shareteam perktest remove <증강id>
/shareteam perktest clear confirm
/shareteam perktest list all
```

**잠금이 둘입니다. 둘 다 있어야 동작합니다.**

1. `config/sharedfate.json` 의 `perkTestCommands` 가 `true`
2. 명령을 치는 사람이 **운영자(권한 4)**

`perkTestCommands` 의 기본값은 `false` 이고, **실제로 노는 서버에는 이 값을 두지 마십시오.**
켜져 있으면 서버가 뜰 때 경고 로그가 남고 접속하는 사람마다 채팅으로 경고를 받습니다.
한 번이라도 쓴 팀은 `/shareteam status` 에 「정상 회차가 아닙니다」가 표시되며, 그 표식은
회차가 끝날 때까지 지워지지 않습니다.

즉시 지급이나 「유산」의 몰수처럼 **고르는 순간에만 일어나는 효과는 재현되지 않습니다.**
덕분에 넣었다 뺐다를 반복해도 아이템이 불어나지 않습니다.

## 소스 빌드

JDK 25에서 실행합니다.

```powershell
# JDK 25 를 설치한 경로로 바꿔 주십시오.
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-25"
.\gradlew.bat build --no-daemon
```

`JAVA_HOME` 을 지정하지 않으면 시스템 기본 JDK 를 따라갑니다. 그것이 21 미만이면
Fabric Loom 을 해석하지 못해 빌드가 시작조차 되지 않습니다. PATH 의 `java` 가 25 여도
`JAVA_HOME` 이 다르면 실패하므로 위처럼 함께 지정하는 편이 안전합니다.
